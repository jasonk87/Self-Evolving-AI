# Weebo 3 bug audit — 2026-10-17

Scope: fixes to the shipped Weebo 3 implementation, not a redesign. Started from `f1a6cc4` on
`ccr-4344bfa1-gl9ayf`. No Weebo 1.x code, credentials or existing model settings changed.

## Bugs fixed

- Connector tests now require a user-started turn; disabling an untested connector no longer bypasses testing.
  Undeclared MCP tools are outside the approved scope. Grants/revocations change a bot's thread identity.
- Bot work rechecks and reserves the shared budgets after startup waits. Bot-launched agents inherit the bot's
  model, effort, sandbox and dynamic-tool scope, count against its budgets, and cannot steer another bot's agent.
- Refused jobs remain failed, repeated stuck-job escalations are suppressed, and reports beyond the digest's
  visible limit are left pending rather than silently marked delivered.
- New conflicting/adjacent calendar events invalidate cached day-sheet calculations; rows outside the current
  horizon are removed from the derived cache, not from source facts.
- Ideas reject expired evidence, refresh available sources before acting, refuse stale unavailable sources,
  prevent duplicate concurrent actions, preserve explicit time-zone offsets, and leave failed draft dispatches
  open for retry.
- Email ingestion reads structured MCP results, ignores failed tool results, and does not treat unread mail as an
  obligation to reply. Fresh connector snapshots remain queryable without pretending they cover a whole mailbox.
- Approval activity updates reach idle clients immediately. The activity slot uses plain words, not shell commands.
- MCP request timeouts cover sending as well as receiving. A noisy server cannot deadlock on its stderr pipe.
  The connector template now includes the manifest its instructions referenced.
- Workflows await actual chief-turn completion, carry results to the next step, reject overlapping occurrences,
  and ignore duplicate completions. Stopped, paused and restart-interrupted runs release their bookkeeping without
  automatically replaying possibly side-effecting work. Chief workflow turns honor the existing background budget
  and plan-usage ceiling; workflow routines share the existing 15-minute minimum repeat interval.

Regression tests are in `tests/weebo/test_weebo3_bugfixes.py`, with an additional real-browser approval/activity
test in `test_weebo3_ui.py`. An existing mail fixture now explicitly supplies `needs_reply: true`; its assertions
are unchanged. No existing test was removed, skipped or weakened.

## Remaining issues needing design decisions

1. **Native connector isolation is incomplete.** Per-thread MCP overrides do not prove inherited global servers
   and ChatGPT apps are disabled. The fallback observes `item/started` and interrupts afterwards, which cannot
   prevent an external side effect. App matching and risk classification are also heuristic. A real pre-execution
   allowlist/isolation boundary, tested against Codex, is needed before relying on unattended external actions.
2. **Onboarding is not an OS sandbox.** A subprocess inherits the host environment and can access the filesystem
   and network. User authorization is now mandatory, but it does not make an untrusted connector safe. Command
   approval classification and broad standing-rule matching likewise are not a complete capability security model.
3. **Fact-checking is advisory, not a publication gate.** Output streams before checks finish; the second pass is
   post-turn, can be unavailable, and does not validate every kind of claim. Enforcing the original reliability
   promise requires holding high-stakes output until a fresh-source check succeeds, with a defined failure policy.
4. **Action verification is partial.** A draft idea is marked done when dispatch is accepted, not when the draft
   finishes. SMS checks provider acceptance, not subsequent delivery. Calendar read-back does not compare every
   requested field. Reports included in a brief are marked delivered before the chief successfully publishes it.
5. **Some derived data can still age.** Existing day-sheet rows do not refresh solely because a related person or
   mail thread is newly added, or a weather forecast ages. Those need explicit dependency/freshness policies.
6. **Direct user bot chats retain the existing budget exemption.** Automated bot and bot-agent turns obey caps;
   the existing direct-user exemption is preserved, rather than silently changing that tested behavior.
